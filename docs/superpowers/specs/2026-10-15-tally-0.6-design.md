# Tally 0.6 Beta: supersets, set types, Apple Watch sync, weekly recap, add-reps shortcut

Date: 2026-10-15. Approved in conversation the same day.

## Intent

Tally is a personal workout tracker (one user, sideloaded with xtool on Windows, free Apple ID).
0.6 makes it closer to Hevy for day-to-day logging and connects it to the Apple Watch Workout app.

Success means: everything below works on the user's iPhone, workouts saved by 0.5 load unchanged,
and Apple Health no longer ends up with two workouts for one gym session.

Constraints: no backend, no paid developer account, builds with xtool in WSL (no Xcode build
system), no automated test target that can run the app's code from Windows. UI copy stays plain
and factual.

## 1. Supersets

Data: `WorkoutExercise.supersetID: UUID?` (optional, so older data decodes). Adjacent exercises
in `Workout.exercises` / `Plan.exercises` with the same ID form one superset.

Behaviour:
- Exercise menu: "Superset with…" lists the other exercises in the workout or plan. Choosing one
  moves it directly after the current exercise (or after the last member of the current
  exercise's superset) and gives both the same ID (reusing an existing ID if either already has one).
- "Remove from superset" clears the ID. Whenever a group is left with one member (after removing,
  deleting or moving an exercise), that member's ID is cleared too (`normalizeSupersets()`).
- Grouped exercises show a 4 pt accent bar on the leading edge of their header row and a
  "Superset" label next to the rest time.
- Rest timer: completing a set starts the rest timer only if the exercise is the last member of
  its superset (or not in a superset). The last member's rest time is used.
- `GymStore.start(...)` and `plan(from:)` copy `supersetID`, so plans keep supersets. New IDs are
  generated per copied group so a plan and its workouts don't share IDs.

## 2. New set types

`ExerciseKind` gains `weightedBodyweight`, `assistedBodyweight` and `distanceDuration`
(raw values are new strings, so 0.5 data decodes). `WorkoutSet` gains `meters: Double?`.

| Kind | Inputs | Display | Volume | Records |
|---|---|---|---|---|
| weightedBodyweight | added kg, reps | `+10 kg × 8` | added kg × reps | heaviest added weight, most reps |
| assistedBodyweight | assistance kg, reps | `−20 kg × 8` | 0 | least assistance (reps > 0), most reps |
| distanceDuration | km, time | `5 km · 25:00 · 5:00 /km` | 0 | longest distance, longest time, best pace (sets ≥ 1 km) |

- Weight fields stay positive numbers; the sign is shown by the kind (header "+kg" or "−kg").
- Time entry: new `TimeField` that fills like a timer (typing 2, 5, 0, 0 shows 25:00). Used for
  `distanceDuration` and replaces the seconds field for `duration` (header becomes "Time").
- Distance is entered in km (decimal), stored in metres.
- `RecordKind` gains `leastAssistance` (lower is better), `longestDistance`, `bestPace`
  (seconds per km, lower is better). Record computation handles "lower is better" kinds.
- `ExerciseDetailView` chart metrics: weighted → heaviest added, reps; assisted → assistance,
  reps; distance → distance, time, pace.
- `SetChange` and `Fmt.set` / `Fmt.record` cover every kind. Plate calculator and weight
  suggestion stay `weightReps` only.
- Library: add "Pull-ups (Weighted)", "Chin-ups (Weighted)", "Dips (Weighted)". Change
  "Assisted Pull-up (Machine)" and "Assisted Dip (Machine)" to `assistedBodyweight`; Running,
  Walking, Cycling and Rowing Machine to `distanceDuration`.
- `ExerciseLibrary.merge` also updates `kind` on built-ins, but only for compatible changes where
  stored values keep their meaning: `duration → distanceDuration` and
  `weightReps → assistedBodyweight`. Any other kind change is ignored.

## 3. Apple Watch sync

Permissions: add read access to `distanceWalkingRunning` and `distanceCycling`. HealthKit only
prompts for types not asked before, so `connect()` is called again on launch when connected.

### Import
- `HealthManager.healthWorkouts: [HealthWorkout]`, loaded on launch, on becoming active and
  after connecting: `HKWorkout` samples from the last 365 days whose source is not this app.
- `HealthWorkout`: id (HK UUID), activity type → name and SF Symbol, start, end, active kcal,
  distance (m), source name. Average and max heart rate are queried when the detail page opens
  (existing `health(for:)` time-window query).
- Not stored in `gym.json`; deleting in Health removes it from Tally.
- History list and month calendar show them mixed in by date with a Watch icon; detail page shows
  tiles (time, distance, kcal, heart rate). Read-only.
- They count for the calendar, week streak, week strip and Training widget snapshot, not for
  volume or records.

### Merge
- `Workout` gains `linkedHealthID: UUID?` (the Watch workout this session is merged with) and
  `savedHealthID: UUID?` (the workout Tally itself saved to Health).
- Overlap rule: a Health workout matches a Tally workout when its type is strength-like
  (traditional or functional strength training, HIIT, cross training, core training, mixed
  cardio) and the overlap is more than half of the shorter of the two.
- On finish: if a matching Health workout exists, set `linkedHealthID` and do not save. Otherwise
  save as now and store the new workout's UUID in `savedHealthID`.
- On every refresh: for Tally workouts from the last 3 days with `savedHealthID` and no link,
  look for a match; if found, delete Tally's own sample from Health, clear `savedHealthID` and
  set `linkedHealthID`. If the delete fails, leave both and try again next refresh.
- Linked Health workouts are hidden from the imported list. The Tally workout's detail page uses
  the linked workout's energy for the kcal tile.
- No Health access or not connected: nothing is imported or merged; everything else works.

## 4. Weekly recap

- `WeeklyRecap` is computed by a pure function from workouts and Health workouts for a week
  (the same calendar week as the rest of the app, `GymStore.weekStart`; Monday to Sunday in the
  user's region) and the week before: workouts, total time,
  volume, sets and their change; Watch activities (count, kcal); records set; muscle levels
  (same calculation as Progress); most improved exercise = largest increase in best estimated
  1RM against that exercise's last session before the week (weight exercises only, needs both).
- Home: from Monday, if last week had at least one workout and `recap.dismissedWeek` isn't that
  week, show a "Last week" card (workouts, time, volume, small muscle figure). Tap opens the
  recap page; ✕ dismisses it for that week.
- Recap page: week dates, tiles with ↑/↓ against the previous week, Watch activities, records,
  muscle map, most improved exercise, Share button (existing week story card).
- Progress gets a "Weekly recap" entry listing past weeks that had workouts.

## 5. Add-reps shortcut

Risk: App Intents need a metadata bundle (`Metadata.appintents`) that Xcode's build produces.
xtool may not produce it.

- First a throwaway spike: one `AppIntent` plus an `AppShortcutsProvider`, built with xtool and
  installed. Pass = the action appears in the Shortcuts app and runs. Fail = this section is
  dropped and the user is told; the spike code is removed.
- If it passes:
  - `AddRepsIntent` in TallyKit (shared by app and widget): parameters exercise
    (`QuickExerciseEntity`, from `RepStorage`) and amount (default 10). Appends a `RepEntry`,
    saves and reloads the reps widget.
  - `AppShortcutsProvider` with a phrase like "Add reps in Tally" (Siri, Action button, Spotlight).
  - A Control Center control (`ControlWidget`) in the widget extension: a button whose exercise
    and amount are chosen when adding it.
  - Medium and large reps widgets get a "+10" button per exercise row (`Button(intent:)`).

## Testing

No automated tests can run the app's code from Windows. Logic is kept in small pure functions
(superset normalisation, rest decision, overlap matching, recap calculation, formatting) so it
can be read and checked in isolation. Each section is built with `xtool dev build` and installed
on the phone, then checked:

- 0.5 workouts, plans and exercises load and display unchanged.
- Superset: rest starts only after the last exercise; plan keeps the superset.
- New kinds: entry, display, records and charts for one exercise of each kind.
- Watch: a Watch-only run shows in History; a Watch strength workout during a Tally session ends
  up as one workout in Health and in Tally, whichever is stopped first.
- Recap numbers match the History list for that week.
- Shortcut adds reps from Shortcuts, Control Center and the widget.

## Out of scope

Tally app on the Watch, RPE, warm-up generator, body measurements, plan folders, notifications.
